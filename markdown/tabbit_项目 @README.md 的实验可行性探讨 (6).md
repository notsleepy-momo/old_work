# 二、 项目的 CV 部分是否过于苛刻？是否需要给 LLM 更多空间？

### **是的，当前的 CV 规则过于苛刻，严重压制了 LLM 的发挥空间，必须进行“解耦重构”。**

### 1. 痛点分析
当前你的 CV 阶段（如 `_fuse_and_dedup_candidates()`）执行了极其严厉的硬编码规则：
*   死角过滤、长宽比 > 5 直接删除、与红框重叠直接删除、强信号自动合并。
*   **后果：** CV 在前置阶段就把许多“不规则”但“正确”的候选家具直接掐死了。LLM 拿到的候选集已经是被严重过滤过的、只剩下规则矩形的“残缺版本”。LLM 只能做极其保守的微调，导致 **LLM 修正前后 F1 几乎没有变化**，LLM 的空间推理能力完全成了摆设。

### 2. 重构原则：CV 负责高召回，LLM 负责约束决策（宁多勿漏）
你应该把 CV 的定位退回至 **“候选生成器 (Candidate Proposer)”**，把过滤和合并的生死大权交给 **“LLM Action-based 机制”**。

#### **具体修改方案：**
*   **放宽 CV 阈值：** 允许长宽比较大、面积较小、或与红框有部分重叠的蓝框（轨迹闭环）进入候选集。
*   **只做代码确定性去重：** 仅使用 IoU 极高（例如 > 0.85）的绝对重叠去重，其余“疑似重叠”作为特征标注出来（例如 `is_overlapping_with_hatch: true`），传给 LLM 决策。
*   **为 LLM 预留 Action 空间：**
    *   在 prompt 里告诉 LLM：“候选框 3（蓝框）和候选框 1（红框）重叠了 40%，且候选框 3 的轨迹闭环特征显示其为独立圆环。你可以选择执行 `DELETE(3)`（认为它是噪声），也可以执行 `ADJUST(3)`（认为它是一把靠在桌子旁的椅子）。”
    *   这样，LLM 就有了真正的**几何与拓扑协调空间**，F1 的提升和 constrained 协议的价值才能在实验里真正体现出来。
