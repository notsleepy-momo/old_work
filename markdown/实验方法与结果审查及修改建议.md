# 实验方法与结果审查及修改建议

审查日期：2026-08-28

## 1. 审查结论

当前实验可以支持“单家庭案例研究、系统调试和方法可行性展示”，但不能支持泛化性、统计显著性或面向 UbiComp 的总体性能结论。最主要的原因不是模型分数本身，而是评估协议、测试 GT 使用方式、消融实现和统计单位存在系统性问题。

本次审查确认了四个会直接改变论文结论的高优先级问题：

1. 旧的 90.0% CLS 报告早于当前预测文件，结果已经过期；按当前预测重算不能复现该结论。
2. 旧主表把 Ours 的 Aligned 结果与基线的 Global 结果比较，协议不一致。B 的房间匹配与平移只能由预测冻结后的独立评分器执行，不能反馈给模型；公平比较必须让所有方法分别使用同一 Global 或同一 Aligned 协议。
3. `skip_trajectory` 原先只切断家具检测阶段的轨迹，RoomAgent 和 BehaviorAgent 仍读取完整轨迹，因此旧模态消融没有真正移除 Human Activity。
4. VLM baseline 原先从测试 GT 提取房屋尺寸、设备坐标和解析失败时的 fallback，存在测试信息泄漏；同时调用脚本传入的 `config/smart_devices.yaml` 只有类别词表，不是当前家庭设备观测。

因此，2026-08-28 以前生成的 comparison、ablation、noise robustness 和 multi-run 数值均应视为历史调试结果。修复后未重新调用 API 的结果不能沿用到论文主表。

## 2. 当前结果的正确解读

当前预测文件 `output/0622/yaml/03_final_0622.yaml` 比旧主评估报告更新。使用修订后的评估代码无 API 重算，得到：

| 协议 | Room F1 | Localization F1 | Semantic F1 | Conditional FNA | Legacy CLS |
|---|---:|---:|---:|---:|---:|
| A. 全局匹配 (Global) | 85.7% | 81.0% | 57.1% | 70.6% | 77.2% |
| B. 房间内对齐匹配 (Aligned) | 85.7% | 85.7% | 61.9% | 72.2% | 79.6% |

A 使用预测绝对坐标；B 先匹配房间，再在每对房间内平移对齐后匹配家具。模型测试/预测生成阶段不读取 GT，预测 YAML 冻结后 GT 才进入独立评分器。B 中计算的房间对应关系和偏移量不得用于重新推理或修改预测。

其中 Semantic F1 要求家具位置 IoU 达标且名称正确，是更合适的端到端语义指标。Conditional FNA 只在已经定位成功的家具中计算，适合分析“检测成功后为何命名错误”，不能单独代表完整系统性能。Legacy CLS 的权重没有经验或理论依据，只保留用于兼容旧结果，不应作为摘要或主结论中的核心指标。

使用现有 baseline YAML 分别按统一 Global 和 Aligned 协议重新评分，得到以下诊断表：

| 协议 | 方法 | Room F1 | Localization F1 | Semantic F1 | Conditional FNA |
|---|---|---:|---:|---:|---:|
| Global | VLM Zero-shot | 46.2% | 33.3% | 25.0% | 75.0% |
| Global | VLM Chain-of-Thought | 0.0% | 50.0% | 35.0% | 70.0% |
| Global | CV-Only | 71.4% | 81.0% | 19.0% | 23.5% |
| Global | Ours | 85.7% | 81.0% | 57.1% | 70.6% |
| Aligned | VLM Zero-shot | 46.2% | 29.2% | 16.7% | 57.1% |
| Aligned | VLM Chain-of-Thought | 0.0% | 0.0% | 0.0% | 0.0% |
| Aligned | CV-Only | 71.4% | 85.7% | 23.8% | 27.8% |
| Aligned | Ours | 85.7% | 85.7% | 61.9% | 72.2% |

这张表只能用于定位现有输出的差异，不能直接用于发表。原因是现有 VLM YAML 由旧的 GT 泄漏实现生成，必须使用修复后的真实智能设备输入重新运行 VLM 后才能形成有效对比。Aligned 不保证比 Global 高：它先要求房间匹配成功，再限制家具只能在对应房间内匹配；VLM CoT 没有正确房间匹配，因此 Aligned 为 0。Ours 与 CV-Only 的 Global Localization F1 相同，当前单家庭结果主要显示语义命名收益，而不是绝对坐标定位收益；论文陈述应准确反映这一点。

## 3. 方法与指标问题

### 3.1 房间指标

旧 RTA 为“正确类型的已匹配房间数 / 已匹配房间数”。漏检房间不进入分母，会系统性抬高结果。修订后 RTA 的分母为完整 GT 房间数，并新增：

- Room Precision = 正确类型且定位匹配的房间数 / 预测房间数；
- Room Recall = 正确类型且定位匹配的房间数 / GT 房间数；
- Room F1 = Room Precision 与 Room Recall 的调和平均。

论文主表优先报告 Room F1，并同时给出 Precision/Recall 供错误分析。

### 3.2 家具语义指标

旧 FNA 是定位 TP 上的条件准确率。检测很差的方法仍可能获得较高 FNA，因此不能把它当端到端语义性能。修订后新增：

- Semantic TP = IoU > 0.2 且预测名称正确；
- Semantic Precision = Semantic TP / 预测家具总数；
- Semantic Recall = Semantic TP / GT 家具总数；
- Semantic F1 = Semantic Precision 与 Semantic Recall 的调和平均；
- Semantic FDR = 1 - Semantic Precision。

IoU 阈值 0.2 偏宽松，应在论文中解释其与小家具和坐标噪声的关系，并补充 0.1、0.3、0.5 的敏感性分析。Centroid F1 可以作为尺寸无关的补充定位指标，但不能替代统一主指标。

### 3.3 面积分层

旧实现只从匈牙利匹配对统计面积层分母。当 GT 数多于预测数时，未匹配 GT 会从分母消失。修订后分层 GT 数直接由完整 GT 家具列表初始化，所有漏检都保留在相应 small、medium、large 分层中。

### 3.4 协议违规与语义误报

旧 Hallucination Rate 混合了三类概念：不在房间允许词表、名称未出现在当前家庭 GT、检测误报；其分母还包含不进入分子的智能设备，导致比例被人为降低。修订后拆分为：

- Protocol Violation Rate：违反房间允许词表的非智能设备预测 / 非智能设备预测总数；
- Semantic FDR：1 - Semantic Precision；
- Conditional FNA：仅用于定位 TP 的命名错误归因。

Protocol Violation Rate 是约束机制检查。约束模型词表违规率更低是预期行为，不能独立证明总体识别性能更好。

## 4. 消融与鲁棒性设计

### 4.1 模态消融

建议采用严格的 2×2 因子设计：

| 条件 | Smart Device | Human Trajectory |
|---|---:|---:|
| Layout Only | 无 | 无 |
| Layout + Device | 有 | 无 |
| Layout + Trajectory | 无 | 有 |
| Full | 有 | 有 |

修订后的 `skip_trajectory` 已同时切断家具检测、RoomAgent 和 BehaviorAgent 的轨迹输入。每个条件必须在同一代码版本、同一模型、同一 prompt 和同一输入版本下重新运行，Full 条件不得复用其他日期的已有预测。每家庭每条件至少重复 5 次；先在家庭内汇总重复运行，再以家庭为统计单位估计 Device 主效应、Trajectory 主效应及二者交互效应。

### 4.2 轨迹时长

项目轨迹文件的 `duration` 单位是分钟，例如 30 秒记录为 `duration=0.5`。FurnitureDetectionAgent 原本按分钟处理，逻辑正确；RoomAgent、BehaviorAgent prompt 和 fallback 阈值使用秒。修订后的 Pipeline 在进入 RoomAgent/BehaviorAgent 前依据 `start_time/end_time` 校验并转换为秒，家具检测仍读取原始分钟文件。

### 4.3 噪声鲁棒性

同一家庭的 5 个扰动 seed 是对同一个实验单位的重复测量，不是 5 个独立家庭。把同一个 baseline 复制 5 次后做 Wilcoxon 会构成伪重复，不能支持总体显著性。修订后的脚本移除了该 p 值。

正确流程为：每个家庭、每个噪声等级运行多个 seed；先对家庭内 seed 求均值；再以家庭为配对单位比较不同噪声等级。应报告家庭级平均变化、效应量、家庭 bootstrap 95% CI，以及性能随噪声强度的曲线。只有一个家庭时只报告描述性 mean/std，不使用显著性语言。

### 4.4 多轮稳定性

旧报告中聚合指标方差较小，但同时存在多个家具实例跨轮名称不一致。聚合分数的低标准差不能推出实例级“高度稳定”。修订后的报告增加：

- 完全一致实例比例；
- 每实例多数票一致率；
- 不一致实例及各名称出现次数；
- 每项聚合指标的最小值、最大值和标准差。

样本规模足够时，再补充 Fleiss' kappa 或 Krippendorff's alpha。报告应使用“聚合分数波动为 X，实例完全一致率为 Y”的描述，不设置未经验证的 3% 稳定阈值。

## 5. 数据规模与标注

当前只有 1 个真实家庭、7 个房间和 20 件 GT 家具。该规模无法估计跨家庭方差，也无法支持泛化或总体显著性。建议最低收集 10–15 个家庭，目标为 20 个以上，并覆盖不同户型面积、房间数、家具密度、轨迹稀疏度和设备数量。

在数据采集前固定纳入标准和排除标准。将家庭划分为开发集与最终测试集；prompt、阈值、名称 alias 和允许词表只能在开发集上调整。最终测试集在实验方案冻结后只评估一次。至少对 20%–30% 的家庭进行双人独立标注，报告房间类别一致率、家具类别一致率以及位置框 IoU 一致性；分歧由第三人或协商裁决。

## 6. 公平对比要求

所有方法都应分别报告 A. Global 和 B. Aligned，并且方法间只能在相同协议内比较，不能把某方法的 A 与另一方法的 B 放在同一排名中。A 衡量绝对坐标性能；B 先匹配房间，再在每对房间内平移对齐后匹配家具。每种方法可使用哪些生成输入应预先列清：户型图、智能设备观测、行为轨迹、外部词表和模型调用次数。VLM baseline 只能读取 `input/Smart_device/smartDevice_{code}.yaml` 的当前家庭观测，模型测试/预测生成阶段不得读取 GT；预测冻结后，测试 GT 才能进入独立评分器计算 A/B 指标。

同时记录以下运行元数据：代码 commit、运行时间、模型名称、endpoint、temperature、prompt 版本、输入文件哈希、随机 seed、API 调用次数和 token 数。成本必须注明是估算值、价格来源和价格日期。当前主 Pipeline 实际模型是 `gpt-4o`；旧报告硬编码的 `gpt-5.4` 标签不可继续使用。

## 8. 必须重新运行的实验

代码修复不会使旧 API 输出自动变成有效实验。正式报告前应按以下顺序重新运行：

1. 冻结代码、prompt、模型、输入和评估阈值；
2. 重新生成 VLM Zero-shot 与 VLM CoT baseline，确认运行日志中不读取 GT；
3. 对四个 2×2 模态条件进行同批次多轮运行；
4. 重新运行约束与 free-form 对比，报告 ProtV 和 Semantic FDR；
5. 在多个家庭上重新运行设备噪声、轨迹稀疏和图像退化实验；
6. 为所有方法生成统一 Global 表与统一 Aligned 表，禁止跨协议排名；
7. 用家庭级 bootstrap CI 和家庭级配对统计替换 seed 级显著性；
8. 保存结构化 JSON、文本表、运行配置和文件哈希，确保数值可追溯。

在完成这些重跑前，最稳妥的论文结论是：系统在一个家庭案例中展示了较好的房间语义和家具定位表现，并显示出相对于现有输出的语义命名改善；跨家庭有效性、统计显著性和鲁棒性仍待验证。
